## 2026-08-16

### 標記軸:指向第一次疑似抬手

播放器下方的紅點原本釘在**警報成立的那一刻**。但警報是「累積夠
`min_events` 次、且 P 持續超過門檻」的**結論**,成立時動作往往已經結束
十幾二十秒——點過去只會看到人站著,看不到想複查的那口菸。

改成釘在**第一次手到臉**上,包含太短而沒被計入的碰臉:確定是抽菸之後
回頭看,那些就是這輪行為的開頭。

實測 `demo_videos/抽菸_持續重複38秒.mp4`(`rule`,`inference_hmdb.yaml`):

```
疑似時刻  4.4 / 5.6 / 10.8 / 15.0 / 20.2 / 24.5
觸發 26.1s → 標記 4.4s     (提前 21.7 秒)
分析路徑  觸發 36.0s → 標記 10.9s
```

途中踩到兩個坑,都值得記著:

- **錨在 S1 階段上根本抓不到**。S1 只在一個很窄的距離帶內才回報
  (`inference/skeleton.py:190`,`near_eff < d < near_eff + 2×move` 且距離
  明顯縮小),10fps 取樣下手常常一步就跨過去。實測整輪 `raises` 是空的,
  標記一路走的是「沒看到抬手」的退路值,**看起來剛好像有在動作**,所以
  沒有立刻發現。改用事件結算時回填的「結束 − 停留」當錨點:事件一定有。
- **改了語意卻沒讓快取失效**。`.analysis/*.npz` 側車檔照載,重開影片看到
  的還是上一版的標記,而且畫面上沒有任何跡象說它沒重跑。`CACHE_VERSION`
  現在 = 3,並補了 `TestCacheVersion` 三項回歸測試釘住這件事。

順帶把警報片段的前置緩衝改成可調(`alarm.clip_pre_sec`,5–30 秒,預設
10)。現在提前量常有 20 秒以上,預設值拍不到動作開頭——診斷框會明講,
不會讓人誤以為是漏偵測。播放器不受此限,整支檔案都在。

### 只有「等待」才做抽菸分析

`presence.smoking_requires_waiting`(預設開)。經過與徘徊的人**連分析都
不做**——不裁 ROI、不跑外觀網路、不推狀態機、不累積次數。

第一版做成「分析照跑,最後才擋掉警報」,一點算力都沒省,與這條規則的
目的相反。改成真的跳過之後(單步中位):

| 方法 | 閘門關 | 閘門開 |
|---|---|---|
| `hybrid` | 43.3 ms | **19.6 ms**(2.2 倍) |
| `rule` | — | 20.3 ms |

純規則省得有限是結構性的:成本 93% 在 YOLOv8-pose,姿態偵測是整張影格
一次、與人數無關,而且不先偵測就不知道誰在等待。

⚠ 「等待」要在場滿 `long_stay` 秒(預設 20)才成立,所以**十幾秒的警報
片段永遠到不了等待**,拿它回頭重跑重現不出這個狀態。

### 警報成立卻沒有片段(兩個獨立的 bug)

- **背景執行緒呼叫 `root.after`**：Tkinter 的任何 API 都只能在主執行緒
  用,三個呼叫點把工作執行緒靜靜弄死——沒有片段,也沒有影格。
- **來源在後錄 4 秒內結束**：`_active_recs` 沒有被收尾,警報跳了、ID 也
  顯示了,片段卻被丟掉。

### GUI 收斂

- 主畫面只留四個開關(徘徊警報 / 等待警報 / 抽菸警報 / 開啟骨架可視化),
  警報清單只顯示片段名稱與縮圖,過程訊息全部移到獨立的診斷框——警報要
  一眼看得出「有幾件」,混進 log 就看不出來了。
- 選方法時跳出**該方法自己的**參數表(`ui/settings_dialog.py`),各方法
  各記各的覆寫值:論文要橫向比較,調鬆 `rule` 不該連帶改到 `hybrid`。
- 補回移動排除開關——先前拿掉主畫面的勾選框卻沒放進參數表,行為沒變但
  使用者失去了唯一的開關,看起來就像規則壞掉。

### 播放器改成標記工具

- **先分析後播放**:點開影片先跑一次判定,標記出來才開始播。結果存成
  側車檔(`.analysis/<檔名>.npz`),**原始影片完全不動**,同一支第二次開
  是秒開(17s → 0.46s)。對話框給三條出口:等它跑完 / 先播放(分析丟到
  背景)/ 不分析。
- **可點選的標記軸**、逐幀、變速、截圖、快捷鍵、循環、全螢幕;無音訊。
- 骨架疊加改吃分析時的快取,不再播放時每幀重跑偵測。
- 分析的姿態偵測改成批次:**2.7 倍加速**。
- 修正播放速度比實際慢(0.68–0.80x):補回解碼與繪圖的時間;60fps 來源
  改用丟幀保同步。

### 影片下載分頁

`yt-dlp` 走影片、錄影走直播,兩條路分開。記錄區是該資料夾的**縮圖清單**
(不是 log),雙擊直接播。修正過一次「狀態一直停在準備中」——進度與記錄
的更新根本沒接上。
