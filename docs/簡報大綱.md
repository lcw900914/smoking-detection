## 第 2 頁|問題:為什麼不偵測香菸?

【版面】
- 監控距離下香菸僅佔數個像素
- 易受遮擋(手掌、口罩)、逆光/低照度下不可見
- 電子菸等新型態外觀差異大,物件偵測難以泛化
- (配圖:監控畫面中香菸區域放大,幾乎不可辨)

【講稿】現行方案都在偵測「菸」這個小物件,根本限制講清楚。
帶出本研究的轉向:菸看不到,但「抽菸的動作」看得到。

---

## 第 3 頁|核心想法:偵測動作序列

【版面】
- 抽菸 = 有明確結構的週期行為:
  舉手靠近嘴(S1)→ 停留吸食(S2)→ 放下(S3)→ 間隔重複
- 單次動作 ≈ 2 秒;完整行為 = 8–15 次重複,週期 20–60 秒
- 與喝水、講電話、擦嘴的差異集中在 **S2 停留模式與長期週期性**

【講稿】強調兩個時間尺度的觀察——這直接對應後面的雙尺度架構。
也預告 hard negative 的難點(喝水在 S1/S3 上幾乎不可區分)。

## 第 4 頁|系統總覽

【版面】(整頁管線圖,由 README「方法」節重繪)
```
影像/RTSP → YOLOv8-pose 偵測+關鍵點 → ByteTrack 多人追蹤
  → 每人:上半身 ROI → 共享 backbone 單幀特徵(128×28×28)
  → 雙時間尺度環形緩衝 → 時序融合頭 → 網路分數
  → 骨架分支:腕-鼻距離 → 停留時長分類 → 事件計數
  → 通報邏輯(排除條件 + 次數門檻)→ 警報/片段錄製
```

【講稿】三個亮點先點名:純 2D 算子、continual inference、
外觀網路 × 骨架規則的雙分支互補。

## 第 5 頁|方法一:Channel-as-Temporal-Buffer(本研究核心)

【版面】
- 每幀特徵 C×H×W 推入環形緩衝;最近 T 幀沿**通道軸**疊成 (T·C)×H×W
- 通道排列 interleave:[c0t0, c0t1, …, c0t15, c1t0, …]
- Conv2d(T·C→T·C, k=1, **groups=C**) 每組恰為同一通道的 T 個時刻
  = temporal convolution 攤平為 2D
- 全模型僅 Conv2d/BN/activation/pooling/Linear — 無 Conv3D、LSTM、attention

【講稿】這頁講最久。數學等價性:1×1 卷積是跨通道線性組合,
通道排的是不同時刻 → 線性組合就是時間加權。
NPU 相容性是賣點:單元測試強制算子白名單。

---

## 第 6 頁|Continual Inference 與雙時間尺度

【版面】
- 新幀只跑一次 backbone,僅重算時序頭 → 算力為滑動視窗重算法的 **1/T**
- 短尺度 T=16, stride=1(單次動作 ~2 秒)
- 長尺度 T=16, stride=8(週期重複 ~13 秒)
- 兩頭 embedding 融合 → cycle score
- (配圖:雙緩衝示意)

【講稿】訓練端 dataset 直接組疊合張量、推理端 ring buffer 逐幀推,
兩條路徑 tensor layout 完全一致——以單元測試鎖死(比對到逐元素相等)。

---

## 第 7 頁|方法二:骨架輔助分支

【版面】
- YOLOv8-pose 一次前向:人物框(給追蹤)+ 17 關鍵點
- 腕-鼻正規化距離 d = dist(腕,鼻) / max(肩寬, 0.55×軀幹高)
  - 除以身體尺度 → 對攝影機距離不變
  - 軀幹高補側面視角(肩寬被透視壓縮)
- 規則推斷 S1/S2/S3;畫面即時可視化(腕-鼻紅線)
- (配圖:GUI 截圖 smoke_run/gui_autotest.png)

【講稿】骨架的價值:可解釋性(看得到「手到嘴」被偵測)+
不需階段標籤即可運作。也誠實講限制:手在臉部是必要非充分條件。

## 第 8 頁|方法三:停留時長的動作語意分類

【版面】(表格)
| 停留時長 | 語意 | 處理 |
|---|---|---|
| < 2 秒 | 戴耳機/扶眼鏡/摸臉 | 不計 |
| 2~5 秒 | 抽菸的一口 | 計一次事件 |
| > 5 秒未放下 | 講電話 | 不計,即時標示 |
- 0.5 秒偵測中斷容忍(骨架閃爍不切碎停留)

【講稿】這是把領域知識變成零成本分類器:同樣「手在臉部」,
時間結構完全不同。講電話是即時判定(不必等放下)。

---

## 第 9 頁|方法四:次數警戒等級與通報邏輯

【版面】
- 90 秒視窗有效事件:1 次→低 0.2、2 次→中 0.5、≥3 次→高 0.8
- 紅色警報 = 非背向 ∧ 非移動中 ∧ 非講電話 ∧ 事件 ≥ N ∧ 持續 2 秒
- EMA 累積 + 雙門檻 hysteresis(觸發/解除分離,防抖)
- 對應行為本質:單次手到嘴什麼都不是,**重複才是抽菸**

【講稿】可分享設計教訓:早期版本次數只佔融合權重 0.4,
數學上永遠推不過觸發線,「設 N 次」形同虛設——
後改為次數主導,通報語意與設定一致。

---

## 第 10 頁|方法五:不可驗證情境的處理(背向)

【版面】
- 背對時 2D 腕-鼻距離失去意義(打鍵盤/撥頭髮都投影在頭附近)
- 朝向判斷:COCO 關鍵點左右語意 → 肩膀 x 順序顛倒 = 背向;鼻點置信度把關
- 背向 → 骨架**棄權**(沒證據 ≠ 有反證)
- 網路分數仍高 → 橘色「無法確認」+ 自動存 hard case(重訓資料來源)
- 逗留警告:久站 + 看不到手 + 位移小

【講稿】設計哲學:不可驗證的案例不誤報、也不靜默消失,
分流成人工可覆核的警示,同時自動累積重訓樣本。

## 第 16 頁|◇ 工程發現(可當花絮或深度問答儲備)

【版面】
- 模型分數對「縮放/重編碼壓縮」敏感 → 測試素材需原生尺寸+近無損編碼
- ROI 平滑跳動保護需「連續拒絕即接受」恢復機制,否則框永久卡死
- 側面視角肩寬被透視壓縮 → 尺度基準改用 max(肩寬, 0.55×軀幹高)
- 持菸時腕距鼻仍有一掌+菸長 → 門檻語意是「手在臉部區域」而非「貼嘴」

【講稿】每一條都是實測踩坑 → 分析 → 修正的完整小故事,
展示工程嚴謹度;審查者常從這裡追問。

## 第 17 頁|限制與誠實分析

【版面】
- 目前狀態:**不漏測,但誤測偏多**
- 根因 1:Domain gap — HMDB51 電影片段 vs 監控俯視角,
  網路對背向辦公動作常給 0.7–0.95 高分(訓練集無此類負樣本)
- 根因 2:「手在臉部」先天歧義,規則分支無法單獨區分摸臉/托腮
- 根因 3:單目 2D 無法驗證背向的手到嘴(物理極限)
- 已有緩解:停留時長分類、次數門檻、移動/講電話/背向排除

【講稿】主動講限制比被問到再擋好。每個根因都接一個 roadmap 項。
