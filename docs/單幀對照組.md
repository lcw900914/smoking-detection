# 單幀對照組(control group)

**日期**:2026-08-18
**目的**:量出「只看一張畫面」能做到多少,好讓多幀骨架時序模型(L1 ST-GCN
基元 → L2 片段組合)的分數有一個可以對照的基準。

---

## 1. 為什麼需要它

主線的整套設計建立在一個假設上:**抽菸與其他手到嘴動作的差別在時間軸上**
(停多久、來回幾次、間隔規不規律),不在單幀的姿勢上。

這個假設從來沒有被量過。如果單幀就能拿到跟時序模型一樣的分數,那 L1/L2
的兩層架構、片段文法、節律統計全部是白做的。對照組就是拿來檢驗這件事的。

---

## 2. 設計:除了時間軸,其他全部對齊

| 變因 | 主線(L1+L2) | 單幀對照組 |
|---|---|---|
| 骨架來源 | `annotations/pose/*.npz` | 同左 |
| 標籤 | `annotations/clip_labels.json` → `taxonomy.deep_index` | 同左 |
| fold 切分 | 種子 42、分層 5-fold、**依段切** | 逐行相同 |
| 指標 | 抽菸維度 AUC、100% 召回下的誤報過濾率 | 同左 |
| 推論介面 | `HierarchicalRecognizer.predict()` | `FrameRecognizer.predict()`,回傳形狀相同 |
| 棄權閘門 | `verifier.decide()` | 同一個函式 |
| **輸入的時間跨度** | **整段(數十秒)** | **單一幀** |

`stage2/train_frame.py` 在**同一次執行**裡把三條路徑一起算完再印表。分開跑
兩支腳本再把數字抄在一起是不行的:fold 不同、可用段數不同,差距有多少是
方法造成的就講不清楚。

### 2.1 「只有一幀」是逐條守出來的

`kinematic_features` 的每側 19 維裡有三維是差分算出來的
(`K_V_DNOSE` 腕鼻距變率、`K_V_H` 腕高變率、`K_SPEED` 腕速)——那是偷看
鄰幀。`graph_features` 的 `(vx, vy)` 兩個通道同理。兩者都在
`frame_baseline.py` 的特徵版面裡被移除,並且有測試守著
(`test_frame_features_depend_only_on_that_frame`:把該幀以外的內容全部
換掉,該幀的特徵不能變)。

留著會讓對照組偷偷變成兩幀模型 —— 跑得出漂亮數字、沒有任何錯誤訊息、
而且整個比較作廢。

### 2.2 只看「手舉起來」的幀

手放在桌上那些幀不含判別資訊:抽菸的人與打字的人在那裡長得一模一樣。
餵進去等於拿段級標籤污染大量中性幀,模型會學成「這段影片的背景姿勢」。

候選幀的條件全是**單幀幾何**,門檻直接沿用 `primitives` 的常數,
確保對照組與規則層看的是同一批幀:

```
K_VALID  >= 0.5                              腕點可見且身體座標系成立
K_H_WRI  >  LOW_WRIST(-0.5)  或  K_D_NOSE < NEAR(0.9)
```

這也對應單幀方法在真實系統裡唯一合理的用法:不可能每幀都跑分類器,
只在「手舉起來」這個便宜的幾何觸發成立時跑一次。

### 2.3 段級聚合

單幀模型一段會吐幾百個分數,要聚合成一個才比得起來。用**每類各取自己最高
的 k 幀平均**(k = max(3, 15% 幀數)):

- 不用 max:一幀爆表太脆。姿態模型會把看不見的手腕以 conf 0.9+ 幻覺在
  衣領上(見「腕點幻覺」教訓),一幀幻覺就能讓整段變警報。
- 不用 mean:候選幀裡混著抬手途中的中性幀,平均會把真正貼嘴的那幾幀稀釋掉。

一幀手都沒舉起來的段**棄權**(抽菸分數 0),但**仍計入評估** —— 主線模型
在那些段上照樣會給分數,把它們挑掉等於幫對照組挑掉難題。

## 3. 兩種架構

| 代號 | 輸入 | 參數量 | 說明 |
|---|---|---|---|
| `mlp` | 單幀運動學 16 維 × 每側 | 6.4k | 腕鼻距/腕耳距/腕高/肘角/肢段長度…,左手鏡像正規化後兩側共用一顆頭 |
| `gcn` | 單幀 13 節點骨架圖 (x, y, conf) | 16.7k | **就是 L1 的 ST-GCN 拿掉時間卷積** —— 直接沿用 `SpatialGraphConv` 與同一份鄰接矩陣,連功能邊、邊重要性遮罩都一樣 |

`gcn` 是比較嚴格的那一組:與 `rule+l1grammar` 的差別只剩「有沒有時間軸」。
`mlp` 換掉的是一整組手工特徵,多一個變因,拿它跟時序比會說不清楚差距從
哪來 —— 所以**只有 `gcn` 掛進 GUI 的方法清單**,`mlp` 留在離線比較裡
(`train_frame.py --arch mlp`),它的數字仍列在下面的表上。

## 4. 結果(2026-08-18,64 段 / 抽菸 6 段)

### 4.1 分層隨機 k-fold(與 `train_l2.py` 同一組 fold)

```
方法                                    抽菸 AUC    100% 召回過濾率
單幀對照組 MLP                             0.891         63.8%
單幀對照組 GCN                             0.802         31.0%
片段文法(規則基元,無學習權重)                    0.733          0.0%
L1 網路基元 + 片段文法                        0.750          0.0%
```

看起來單幀完勝時序。**但這張表是錯的**,理由在下一節。

### 4.2 捷徑探針揭穿它

同一次執行的探針:只餵「軀幹傾斜 / 遠近 / 朝向」這 7 維、一個手臂特徵
都不給 —— **抽菸 AUC 0.94**。

這 7 維完全不含「手在做什麼」的資訊。它能分得出來,只可能是因為資料本身
在場景維度上可分:抽菸正樣本只有**兩個錄影場次**(20260708 五段、
20260709 一段),負樣本散在 07-09 ~ 07-15 六個場次。分層隨機切法會把同一場
錄影的段同時放進訓練與驗證,模型記住機位就能得分。

### 4.3 依場次切之後(`--split session`,訓練與驗證不共用機位)

```
方法                        分層隨機    依場次      變化
單幀對照組 MLP                0.891  →  0.609     −0.282
單幀對照組 GCN                0.802  →  0.661     −0.141
捷徑探針                      0.943  →  0.652     −0.291
片段文法                      0.733  →  0.733      0
L1 網路基元 + 片段文法           0.750  →  0.750      0
```

**結論在這裡:**

1. **兩個單幀對照組都崩了**,掉幅與捷徑探針的掉幅同一個量級。原本的
   優勢是記憶機位,不是辨識動作。
2. **時序那兩條完全沒動。** 因為片段文法沒有可學參數,學不到場景,
   自然也沒有東西可以崩 —— 這是無參數方法在小資料上的實質優勢,
   不只是「比較保守」而已。
3. **跨場次驗證下,時序方法勝出 0.089 ~ 0.141 AUC。** 原本的假設
   (「差別在時間軸上」)在現有資料下站得住。

### 4.4 混淆矩陣(依場次切,64 段 / 抽菸 6 段)

**先講一件事:這個任務不能看正確率。** 64 段裡 58 段是負樣本,「全部猜
不是抽菸」就有 **90.6% 正確率**,而且完全沒有用(召回 0%)。下面每個
方法都在三個操作點各印一次 2×2,要看的是**漏測**與**誤報**。

#### 門檻 0.25(`verifier.MIN_SMOKING`,系統實際在用的那條線)

| 方法 | 漏測 | 誤報 | 召回 | 精確 | F1 | 正確率 |
|---|---|---|---|---|---|---|
| 單幀 MLP | 2 | **29** | 67% | 12% | 0.21 | 51.6% |
| 單幀 GCN | 1 | **28** | 83% | 15% | 0.26 | 54.7% |
| 片段文法 | 2 | 15 | 67% | 21% | 0.32 | 73.4% |
| L1 + 片段文法 | 2 | 15 | 67% | 21% | 0.32 | 73.4% |

同樣的召回水準下,**單幀的誤報將近時序的兩倍**(29 / 28 vs 15)。
第二階段是誤報過濾器,誤報翻倍等於這個模組沒有作用。

#### 最佳 F1 門檻(過擬合驗證集,只當上界參考)

| 方法 | 門檻 | 漏測 | 誤報 | 召回 | 精確 | F1 |
|---|---|---|---|---|---|---|
| 單幀 MLP | 0.484 | 3 | 12 | 50% | 20% | 0.29 |
| 單幀 GCN | 0.468 | 2 | 13 | 67% | 24% | 0.35 |
| 片段文法 | 0.866 | 3 | 4 | 50% | 43% | 0.46 |
| **L1 + 片段文法** | 0.551 | 2 | **7** | 67% | 36% | **0.47** |

#### 100% 召回(一段都不漏)

| 方法 | 門檻 | 誤報 | 擋掉的負樣本 |
|---|---|---|---|
| 單幀 MLP | 0.011 | 54 / 58 | 4(6.9%) |
| 單幀 GCN | 0.002 | 54 / 58 | 4(6.9%) |
| 片段文法 | 0.000 | 58 / 58 | 0 |
| L1 + 片段文法 | 0.000 | 58 / 58 | 0 |

**這一列全部很難看,而且它才是誠實的。** 系統的紅線是「降級不否決」——
複核不准把真警報壓掉。在那個前提下,現在**沒有任何一個方法擋得掉有意義
比例的誤報**:文法在最低的正樣本上就給 0 分(那兩段腕點可見率 4% / 18%,
根本量不到手),所以門檻只能壓到 0,誤報一個都擋不掉。

換句話說,離線 AUC 0.75 聽起來還行,但**換算成實際能用的操作點是 0%**。
瓶頸不在模型排序能力,在那幾段「骨架根本看不到手」的正樣本。

#### argmax 落在哪裡(模型把負樣本當成什麼)

```
單幀 MLP   實際抽菸(6):其他 5、抽菸 1
           實際其他(58):其他 46、抽菸 9、喝水 3
單幀 GCN   實際抽菸(6):其他 5、抽菸 1
           實際其他(58):其他 45、抽菸 10、喝水 3
```

六類裡只有「其他 / 抽菸 / 喝水」被用到 —— 現有標籤本來就只有抽菸與
`other_neg`/`desk_work` 兩種,講電話 / 扶眼鏡 / 抓頭髮沒有任何訓練樣本。
**現在跑的實際上是二分類**,六分類要先用 `scripts/label_tool.py` 複標。

---

### 4.4 這個數字的可信度邊界

- 抽菸正樣本只有 6 段、兩個場次,其中一個場次只有 1 段。驗證 20260708
  那一折,訓練集只剩 1 段正樣本 —— 那一折的模型必然很差,腳本會標
  「⚠ 訓練集正樣本不足」。**這不是實作問題,是資料的極限。**
- 依場次切之後探針仍有 0.65(不是 0.5),代表殘留的場景相關性還在。
- 全域特徵維持預設關閉(`USE_GLOBAL_DEFAULT = False`):打開的話分層隨機
  下 MLP 會從 0.891 跳到 0.968,那 0.077 全部是捷徑。

治本仍然只有一條:**補跨場景、跨人物的抽菸正樣本**。這與 L2 訓不動是同一個
瓶頸,不是兩個問題。

## 5. 怎麼用

```bash
# 與 train_l2 同一組 fold(可比,但含場景捷徑 —— 只拿來對照 L2 的數字)
python -m stage2.train_frame --arch mlp --l1 checkpoints/hier_l1.pt

# 依錄影場次切,訓練與驗證不共用機位 —— **要下結論請用這個**
python -m stage2.train_frame --arch mlp --split session --l1 checkpoints/hier_l1.pt
python -m stage2.train_frame --arch gcn --split session --l1 checkpoints/hier_l1.pt

# 單段推論看說明
python -m stage2.frame_baseline --ckpt checkpoints/frame_mlp.pt --limit 3
```

GUI / CLI 上是方法清單裡的一格:

- `rule+frame_gcn` — 純規則 + 單幀對照組(單幀骨架圖)

它走 `inference/verifier.py` 的 `frame-*` 模式,與 `l1+grammar` 共用同一個
「降級不否決」判定邏輯,所以換選單那一格就換掉整條複核路徑,其餘全部不動。

`mlp` **不在選單上**(理由見第 3 節),要它的數字就跑
`train_frame.py --arch mlp`,權重不會被任何方法載入。

**這一格是對照組,不是要拿來用的方法。**

## 6. 外觀那一組(YOLO26-cls):目前被資料擋住

### 6.1 先講清楚 YOLO26 有什麼

Ultralytics 的 YOLO26 提供的任務是 **detect / segment / pose / classify /
obb / sem**,**沒有內建的「人體動作辨識」模型**。單幀判動作在這個生態系裡
對應的是 `yolo26-cls`:對裁好的人物影像做影像分類 —— 類別要自己定、裁切
要自己準備、資料要自己標。骨架仍然由 pose 模型提供,它負責決定「哪些幀值得
裁」;`yolo11-pose` / `yolo26-pose` 換上去就是換一顆感測器,不改變架構。

### 6.2 為什麼還是值得做

骨架對照組與主線時序模型看的都是**座標**,座標裡沒有菸。手停在嘴邊 1.5 秒,
抽菸與喝水的骨架幾乎一模一樣 —— 這正是 57 段誤報分析的結論。外觀模型是唯一
有機會直接看到「手上那根白色細長物」的路徑。

### 6.3 被什麼擋住

`stage2/export_crops.py` 已經寫好(候選幀 → 上半身正方形裁切 + manifest,
依段記錄以免切 fold 時洩題),但它預設會**拒絕匯出**:

> 2026-08-18 實測 `alarms/clips` 底下每一段(含最新的 08-16)都把綠色人物框、
> 青色骨架、紅色腕-鼻線與紅色警報框**畫進畫面才存檔**。

這不是雜訊,是**直接的標籤洩漏**:紅框與紅線只在規則判定成立時才畫,外觀
模型只要學會「有沒有紅線」就贏了,完全不必看菸。學到的會是「上一版規則
怎麼判」。

守門用的是飽和純色像素佔比(`overlay_ratio`),實測有疊加層的片段落在
0.47%,門檻 0.2%。

**解法**:GUI 的錄影疊加開關關掉(關 = 錄乾淨影像)之後重錄一批,再跑
`export_crops.py`。這件事跟「補跨場景正樣本」可以一起做 —— 反正都要重錄。
