# 兩層骨架時序模型(淺層基元 → 深層組合)

取代 `stage2/model.py` 的攤平 PoseTCN。差別不在「換一個網路」,
而在**判斷的組織方式**:不再由一個網路直接從骨架吐出「抽菸」,
而是先把動作解析成看得懂的基元,再由基元的**序列**組合出具體動作。

```
節點序列 (T,17,3)
   │
   ├──→ 拓樸圖特徵 (T,13,5)  平移+尺度正規化,不旋轉
   └──→ 運動學特徵 (T,45)    身體座標系裡的角度與距離,旋轉不變
            │
            ▼  L1 PrimitiveNet(ST-GCN + 運動學支流,10 萬參數)
   逐幀基元:靜置 / 舉手 / 停留臉部 / 放下 / 其他活動   ← 淺層
            │
            ▼  分段
   片段序列:[舉手 0.6s] [停留 1.2s, 腕鼻距 0.46] [放下 0.8s] …
            │
            ▼  L2 CompositionNet(時間感知 Transformer,2 萬參數)
   具體動作:抽菸 / 喝水 / 講電話 / 扶眼鏡 / 抓頭髮 / 其他   ← 深層
```

---

## 1. 為什麼分兩層

**資料量。** 端到端要學「座標 → 抽菸」,現有 87 段片段遠遠不夠。
拆開之後兩層的資料處境完全不同:

| | 監督訊號 | 現有數量 | 來源 |
|---|---|---|---|
| L1 淺層 | 逐幀基元 | 17,338 幀×手,其中 7,186 有標籤 | **規則自動產生,不用人標** |
| L2 深層 | 片段級動作 | 64 段(抽菸只有 6 段) | 人工標記 |

L1 的標籤是免費的,而且再多錄影片就自動變多。L2 的輸入被壓成十幾個
token,參數量壓到 2 萬,才有機會用幾十段學起來。

**可解釋。** 誤判時看得到是哪一層錯:基元時間軸印出來,是「停留」判錯,
還是「停留 1.2 秒 × 3 次」被組成了抽菸,一眼分得出來。

**可換。** 抽菸與喝水的判準要調,改 L2;姿態模型換掉,只重訓 L1。

## 2. 拓樸圖(`stage2/graph.py`)

13 個節點(COCO 前 13 點,砍掉膝與踝——判別動作全在手臉之間,
腿部在辦公室場景常被桌子遮擋,留著只是噪聲)。

邊分兩種:

- **解剖邊**:真實骨頭連接,決定向心/離心分區。
- **功能邊**:腕↔鼻、腕↔耳、腕↔眼、腕↔腕。不是骨頭,但正是本任務的
  判別關係。加進圖裡,訊息一步就傳到,不必繞腕→肘→肩→鼻四層。

鄰接矩陣切成三個分區(自身 / 向心 / 離心),各自度正規化;另掛一個
可學的邊重要性遮罩——拓樸給的是「哪些邊存在」,遮罩學的是「哪些邊重要」。

**為什麼要圖而不是攤平向量**:攤平之後「腕」和「膝」在向量裡只是相鄰的
兩個數字,模型得自己從資料學出「腕接肘、肘接肩」。資料只有幾十段時
學不出來。把拓樸寫進鄰接矩陣,等於免費送一個正確的歸納偏置。

## 3. 兩條輸入流(`stage2/kinematics.py`)

刻意用不同的不變性:

**圖流** `graph_features()` → (T,13,5):平移+尺度正規化,**不做旋轉對齊**。
攝影機固定俯視,人朝哪邊站本身就是資訊(背對時腕-鼻距離無意義)。

**運動學流** `kinematic_features()` → (T,45):在**身體座標系**裡算,
對相機滾轉與人物側傾完全不變。

> 身體座標系:原點 = 雙肩中點;尺度 = max(肩寬, 0.55×軀幹高);
> up = 單位向量(肩中點 − 髖中點);right = up 順時針 90°。

每側 19 維,包含使用者要的「手的相對角度」:

| 量 | 意義 |
|---|---|
| 腕-鼻距離、腕-耳距離、腕-眼距離 | 手靠近臉的哪個部位 |
| 腕相對鼻的方位單位向量 | 手在鼻子的哪個方向(不用角度是為了避免 ±180° 跳變) |
| 上臂方向、前臂方向、肘角餘弦 | 手臂的姿勢 |
| 腕高(相對肩線)、腕高減眼高 | 舉多高;高過眼睛是抓頭髮的關鍵 |
| 腕-鼻距離變率、腕高變率、腕速 | 舉手/放下的判準 |

外加 7 維全域量(軀幹傾斜、遠近、朝向 one-hot、有效性)。

**兩級有效性(重要)**:`K_VALID` 只要求腕點可見與身體座標系成立;
`K_FACE_OK` 另外要求鼻點可信。綁在一起會出事——俯視角有 **66%** 的幀
鼻點不可信,若一併棄權,連「手放在腿上沒動」這種確定的事實都標不出來。
分開之後逐幀標籤覆蓋率從 30% 提到 48%。

## 4. 淺層基元(`stage2/primitives.py`)

詞彙五類:`靜置 / 舉手 / 停留臉部 / 放下 / 其他活動`。

**標籤由規則產生,不叫人標。** 「舉手」就是腕-鼻距離在縮小,這種東西
人標不會比公式準,只會比較慢而且不一致。門檻附近的模糊帶一律標成
`−1`(ignore),不進損失——寧可少教,不要教錯。

那為什麼還要網路?規則在三種情況會壞掉,而網路能從整段時序與整張圖補回來:
1. 腕點被遮擋或被幻覺(手背在身後時,姿態模型會把腕點畫在衣領上)
2. 鼻點不可信時規則整段棄權,網路仍可由肘與肩推斷
3. 門檻邊界抖動——規則會在 near 附近來回跳,網路輸出平滑得多

**分段**產出的 `Segment` 帶 21 維屬性(時長、最小腕鼻距、最小腕耳距、
最高腕高、肘角、速度、有效比例……),這些就是深層的輸入單位。

### 兩個踩過的坑,已寫成測試

**缺值不能填 0。** 鼻點不可信時腕-鼻距離被清成 0,若拿去取 min 會得到
「腕鼻距 0.00」——也就是最強的抽菸證據。缺值一律填 `FAR = 3.0`(手離臉
很遠),另外用 `A_FACE_RATIO` 記錄「這段到底量到沒有」。

**沒量到 ≠ 有。** L1 會在鼻點整段不可信的地方也預測「停留臉部」
(它從手臂幾何推的)。那是合理的預測,但**不是手到臉的證據**,所以
`find_cycles()` 直接跳過這種片段。計入等於把「不知道」當成「有」,
正是這個專案一路在對付的誤報來源。
「量到了沒」用**幀數**(≥3 幀)而不是比例:同樣 3 幀量到,0.5 秒的片段
是 60%、2 秒的片段是 15%,但證據一樣多。

**沒有輸入就不該有輸出。** L1 對每一幀都會給答案,包括腕點根本偵測不到
的幀。實測有片段 96% 的幀量不到手腕,卻照樣被切出六段「停留臉部」。
`analyze()` 在走 L1 路徑時,會把 `K_VALID = 0` 的幀退回棄權,片段自然斷開。
注意只遮這一種——鼻點不可信、門檻模糊帶那兩種棄權**不遮**,那裡手臂幾何
是在的,由網路補上正是 L1 存在的理由。

**武裝機制**(承接第一階段的教訓):「停留」要採信,前面得先看到手離臉
夠遠。幻覺腕點恆定懸停,永遠不會先遠離再靠近;真的把手舉到嘴邊一定會。
判定直接查腕-鼻距離歷史,而不是要求「前一個片段必須是舉手」——舉手只有
半秒,遇到遮擋很容易被切碎而消失。

## 5. 深層組合(`stage2/hier_model.py`、`stage2/composition.py`)

片段 token = 基元 one-hot ‖ 側別 ‖ 21 維屬性 ‖ L1 嵌入(16 維)。

序列編碼用 Transformer 而非 GRU:片段序列很短(通常 10–30 個 token),
但判準是「兩兩之間像不像」(抽菸的每一口長得幾乎一樣)——自注意力天生
在算兩兩關係。位置編碼直接編**真實時間(秒)**,不是序號:兩段停留差
2 秒還是 40 秒,是抽菸與否的關鍵。

另有 16 維**節律統計**(停留次數、時長的均值/標準差、間隔的變異係數、
停留佔比、腕耳/腕鼻比……)直接接到分類頭前。節律是抽菸最強的判準,
但要 Transformer 從十幾個 token 自己學出「變異係數」這種二階統計,
以現有資料量不現實。統計量用**固定常數標準化**而非 BatchNorm——推論時
常常 batch=1,BatchNorm 的 train/eval 差異是小資料專案最常見的翻車點。

### 片段文法(無參數的後備路徑)

L2 需要標籤才能訓練。標籤到位前,同一組片段/統計餵給 `grammar_scores()`
也能出分數,判準都能寫成一句話:

| 類別 | 判準 |
|---|---|
| 抽菸 | 手到嘴、每口 0.4–3 秒、來回多次、肘彎;≥2 次且間隔規律再加成 |
| 喝水 | 同樣到嘴,但單次較長(1–5 秒)、次數少 |
| 講電話 | 貼**耳**(腕耳/腕鼻 < 0.75)、停留 > 4 秒、幾乎不放下 |
| 扶眼鏡 | 眼睛高度、極短(< 1.2 秒)、幾乎不動 |
| 抓頭髮 | 停在臉部時手**高過眼睛** |
| 其他 | 手根本沒到臉,或到了但不符合上面任何型態 |

多條件用**幾何平均**合取而不是連乘:連乘會讓條件多的類別天生吃虧
(抽菸五條、抓頭髮兩條,同樣每條 0.8,連乘 0.33 對 0.64,抓頭髮永遠贏)。

`HierarchicalRecognizer` 有 L2 權重就用學的、沒有就用文法,**介面不變**。

## 6. 現在的數字

**L1(5-fold,64 段,規則有把握的幀上)**

| 基元 | 召回 |
|---|---|
| 靜置 | 0.86 |
| 舉手 | 0.82 |
| 停留臉部 | 0.90 |
| 放下 | 0.83 |
| 其他活動 | 0.52 |
| **整體** | **0.707 ± 0.018** |

四個有語意的基元都在 0.82–0.90;整體被「其他活動」拉低,那是概括類,
本來就沒有一致的樣貌。100 epoch 時 train 0.737 / val 0.738——這個規模
是**欠擬合**,不是過擬合,所以 30 epoch 的 0.589 該給的是訓練時間,
不是更多正規化。

**深層:抽菸維度 AUC(64 段,正樣本 6 段)**

| 淺層 | 深層 | AUC |
|---|---|---|
| 規則 | 片段文法 | 0.733 |
| **L1 網路** | **片段文法** | **0.750** |
| L1 網路 | 學習版 L2(5-fold) | 0.580 |

兩件事:

1. **L1 有幫助**——同樣的文法,淺層換成訓練過的網路,AUC 0.733 → 0.750。
2. **學習版 L2 輸給無參數的文法,而且輸得不冤:6 段正樣本學不動
   2 萬個參數。** 這是資料量的問題,不是架構的問題。在補到足夠正樣本
   之前,推論不要載入 L2 權重——`HierarchicalRecognizer` 不給 `l2_ckpt`
   就會自動走文法。`train_l2.py` 每次跑完都會自己比一次並印出結論。

## 7. 真正的瓶頸:一半的片段沒有可用的骨架

把 64 段的關鍵點品質攤開看:

| 量 | 數值 |
|---|---|
| 鼻點可信的幀比例(中位) | 0.26 |
| 鼻點可信幀 < 20% 的片段 | **30 / 64(47%)** |
| 6 段抽菸正樣本中,腕點可見率 | 0.04、0.18、0.76、0.87、0.95、1.00 |

**兩段人工標為抽菸的片段,腕點可見率只有 4% 與 18%**——姿態模型基本上
看不到那個人的手臂。這種片段不管上面接什麼模型都判不出來,而且它們正是
俯視角 + 背向的典型情況(第一階段實測 78% 背向)。

所以現階段的天花板是**姿態偵測**,不是動作模型。骨架看得清的片段
(例如 `alarm_track2_20260708_153431`,可見率 100%)兩層模型判得很乾淨:
四次「舉手 → 停留 1.8 秒 → 放下」,抽菸 0.87。

## 8. 要讓深層真的能學,缺的是什麼

依重要性排序:

1. **抽菸正樣本**(唯一硬門檻)。6 段不夠,而且其中 2 段骨架不可用,
   實際只有 4 段。擺拍錄到 30–50 段是起點。
2. **能看到骨架的視角**。換鏡位、降低俯角、或對背向情況直接棄權
   (第一階段已有 `estimate_orientation` 閘門)。這一項不做,再多資料
   也有一半是廢的。
3. **其餘四類的標籤**。喝水 / 講電話 / 扶眼鏡 / 抓頭髮目前各 0 段。
   標記工具已經加上這四顆按鈕(`scripts/label_tool.py`);現有的 58 段
   `other_neg` / `desk_work` 是 2026-07 的粗類,裡面混著扶眼鏡與抓頭髮,
   做六分類前應該複標。
4. **長時窗**。現有片段只有 13 秒,一根菸的節律根本放不進來。
   路 B 的 60–90 秒滾動節點緩衝到位後,節律統計的權重才該調高。

## 9. 用法

```bash
# 淺層:不需要任何人工標籤,現在就能跑
python -m stage2.train_l1                      # 5-fold + 全量重訓
python -m stage2.train_l1 --dump 3             # 另外印 3 段的基元時間軸

# 深層:需要片段標籤
python scripts/label_tool.py                   # 先標(1-8 動作,9/0/- 排除)
python -m stage2.train_l2 --l1 checkpoints/hier_l1.pt

# 推論(不給 --l2 就走片段文法,目前比較準)
python -m stage2.infer_hier --l1 checkpoints/hier_l1.pt --limit 5
```

程式介面:

```python
from stage2.infer_hier import HierarchicalRecognizer
rec = HierarchicalRecognizer(l1_ckpt="checkpoints/hier_l1.pt")
out = rec.predict(kpts, fps=10.0)     # {"scores", "top", "source", "analysis"}
print(rec.explain(kpts, fps=10.0))    # 基元時間軸 + 節律統計 + 判定理由
```
