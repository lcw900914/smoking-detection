# 第二階段過濾器 — 模型架構設計

定位:**級聯驗證器(proposal → verification)**。第一階段維持高召回,
負責圈出「疑似抽菸」的人與時段並錄下 bounding box 範圍的影像與節點;
第二階段對候選做離線二次檢測,**過濾誤測**。

設計原則(已定案):
1. 判定依據以「一段時間的重複節律」為目標型態
2. **降級不否決**:第二階段判非抽菸 → 警報停留橘色「待人工複查」,
   確認為抽菸才升紅色;召回由結構保證不下降
3. 第二階段離線執行,**不受邊緣算子限制**(可用 GRU/Transformer/3D CNN)

---

## 1. 輸入資料(第一階段供給)

每個候選(一次第一階段警報)打包:

| 項目 | 形狀/格式 | 來源 |
|------|-----------|------|
| 節點序列 | (T, 17, 3) — x, y, conf @10fps | 管線補錄(路 B);原型期由片段離線回抽 |
| 人物框序列 | (T, 4) xyxy | 同上 |
| 事件時間戳 | [(t₁, dwell₁), …, (tₙ, dwellₙ)] | 第一階段計數器現成輸出 |
| 乾淨影像裁切 | 每事件 16 幀 × 112×112(手-嘴區域) | 路 B(**無疊加**;現有片段烙印疊加層,不可用於外觀訓練) |

時窗:節律版需 T ≈ 60–90 秒;原型期先用現有 14 秒片段(單事件驗證版)。

## 2. 架構總覽(兩層四模組)

```
節點序列 (T,17,3)
  │
  ▼ M1 正規化(無參數)
每幀特徵 f_t ∈ R^85
  │
  ▼ M2 骨架時序編碼器(每事件一段視窗)     M3 外觀編碼器(第二期)
事件嵌入 e_i^pose ∈ R^128                  e_i^app ∈ R^128
  │                                          │
  └────────────┬─────────────────────────────┘
               ▼ M4 事件序列節律模型(Level B)
   事件 token 序列 [(e_1,Δt_1), …, (e_n,Δt_n)] + 節律統計特徵
               │
               ▼ 分類頭(多分類)
   {smoking, drinking, phone, desk_work, other} + 信心值
               │
               ▼ 決策:P(smoking) ≥ τ_up → 升紅色;否則停留橘色待複查
```

## 3. 模組規格

### M1 節點正規化(核心前處理,無參數)

消除攝影機距離、人物位置、解析度的影響——不同鏡位的動作落到同一特徵空間:

```
中心化:p'_j = p_j − p_center        p_center = 雙肩中點(缺則 bbox 中心)
尺度化:p''_j = p'_j / s             s = max(肩寬, 0.55×軀幹高)(沿用第一階段定義)
置信度:conf < 0.3 的節點座標置 0,並保留 conf 作為輸入通道(模型自行學會忽略)
速度:  Δp_j = p''_j(t) − p''_j(t−1) (一階差分,補動作動態)
```

每幀特徵:17×2(座標)+ 17×2(速度)+ 17(conf)= **85 維**。
不做旋轉對齊(攝影機固定俯視,朝向本身是資訊)。

### M2 骨架時序編碼器(每事件)

對每個第一階段事件 tᵢ,取視窗 [tᵢ−3s, tᵢ+3s](60 幀)的正規化特徵:

```
輸入 (60, 85)
→ TCN:Conv1d(85→64, k=5, dilation=1) + BN + ReLU
        Conv1d(64→128, k=5, dilation=2) + BN + ReLU
        Conv1d(128→128, k=5, dilation=4) + BN + ReLU   (感受野 ≈ 全視窗)
→ 時間 GAP → e_i^pose ∈ R^128
```

選 TCN 的理由:小資料穩定、平移不變、比 GRU/Transformer 不易過擬合;
約 10 萬參數。之後資料多了可換輕量 Transformer,介面不變。

### M3 外觀編碼器(第二期,可先跳過)

事件峰值附近的手-嘴區域乾淨裁切(16 幀,112×112)→ X3D-XS 或
R(2+1)D-18 截斷 → e_i^app ∈ R^128。負責分「持菸手勢 vs 握杯 vs 持手機」
的細粒度外觀——這是純骨架分不開的部分。**依賴路 B 的無疊加錄製。**

### M4 事件序列節律模型(Level B)

```
事件 token:u_i = [e_i^pose ‖ e_i^app? ‖ dwell_i ‖ log(Δt_i) ‖ d_min_i]
節律統計(序列級,手工特徵直接 concat 到分類前):
  事件數 n、間隔 Δt 的 mean/std/變異係數(週期性:CV 小 = 規律)、
  dwell 的 mean/std、事件嵌入兩兩 cosine 相似度均值(抽菸每口長得像)
序列編碼:2 層 Transformer encoder(d=128, 4 heads,
          以 Δt 做時間間隔位置編碼)或 GRU(資料少時)
  → 序列嵌入 z ∈ R^128
分類頭:MLP([z ‖ 節律統計]) → 5 類 logits
```

n=1(只有一個事件,如路過抽兩口沒錄滿)時退化為單事件判定——
Level B 天生支援變長,不需特例。

### 決策邏輯(降級不否決)

```
第一階段紅色警報 → 立即降為橘色「疑似(二次驗證中)」
第二階段:P(smoking) ≥ τ_up(預設 0.7)→ 升紅色
          否則             → 停留橘色,進待複查佇列
永不硬性取消;τ_up 可依人工複查回饋調整
```

## 4. 訓練計畫

### 資料

| 來源 | 角色 | 狀態 |
|------|------|------|
| 58 段已錄警報片段(誤報為主) | hard negatives(drinking/phone/desk_work/other) | **已有**,標記工具進行中 |
| 場域擺拍抽菸(站/坐、多角度、多人次) | positives | **待錄——唯一硬門檻** |
| 常態節點錄製(路 B 上線後) | 追加負樣本(免費) | 待實作 |

標籤沿用 `annotations/clip_labels.json` 的五類。

### 分期

- **Phase 0(現在,不等資料)**:離線回抽腳本把 58 段片段轉成節點序列;
  M1+M2 以「誤報類別互分」(drinking vs desk_work vs …)驗證骨架特徵
  管線可行;M4 以合成事件序列(規律 vs 爆發間隔)驗證節律可學
- **Phase 1(有正樣本後)**:M1+M2+M4(純骨架)以 14 秒單事件窗訓練
  五分類——第一個真正的過濾器,可上線量測誤報過濾率
- **Phase 2(路 B 資料累積後)**:拉長至 60–90 秒節律窗;加入 M3 外觀流

### 訓練配置

- 損失:CE(類別權重反比頻率);資料極小 → dropout 0.3、weight decay、
  early stopping、**leave-one-session-out** 交叉驗證(同一場次不得跨 train/val)
- 增強(骨架序列):時間抖動與變速(0.8–1.2×)、節點座標高斯噪聲、
  隨機關節 dropout(模擬遮擋)、水平翻轉(左右關節索引對調)
- 評估主指標:**固定 100% 正樣本召回下的誤報過濾率**
  (在 57 段既有誤報上量,直接對應實用價值)

## 5. 與第一階段的介面(路 B 改造點)

1. 管線對每個 track 常態維護 90 秒節點滾動緩衝(17×3 float @10fps,
   每人每分鐘 ~120KB,成本近零)
2. 第一階段警報 → 打包候選(節點序列 + 事件戳 + 乾淨裁切)寫入
   `candidates/` 佇列
3. 第二階段 worker(獨立執行緒/行程,GPU 空檔執行)取件推理,
   回寫升級/保持結果;GUI 顯示「二次驗證中 → 已確認 / 待複查」
4. 錄製同時落地乾淨影像與疊加版(疊加改為顯示時即時渲染,
   或雙路輸出),供 M3 訓練
